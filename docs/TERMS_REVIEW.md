# 키움 Open API 약관 검토와 구현 통제

> 검토 기준일: 2026-08-25  
> 이 문서는 구현 범위를 정하기 위한 기술·운영 검토이며 법률 자문이 아니다.

## 1. 적용 범위 결론

미국주식 REST API의 직접 기준은 로컬 [AG001_110.pdf](../AG001_110.pdf)와 키움의 공식 [오픈 API 서비스 이용약관](https://download.kiwoom.com/deploy/AG001/pdf/AG001_110.pdf)이다.

- 문서 제목: `오픈 API 서비스 이용약관`
- 제정: 2025-02-20
- 최신 개정: 2026-06-01
- 시행: 2026-07-02
- 분량: 9쪽
- 키움의 [개정 공지](https://bbn.kiwoom.com/bbs/VBbsNoticeNOPAZPagingDetailView?seqid=41)는 개정 사유를 해외주식 API 서비스 추가라고 명시한다.
- [미국주식 신규 지원 공지](https://bbn.kiwoom.com/bbs/VBbsNoticeNOPAZPagingDetailView?seqid=48)와 [REST API 소개](https://openapi.kiwoom.com/intro?dummyVal=0)는 현재 REST API 지원 상품을 국내주식·미국주식으로 구분한다.

사용자가 제공한 2021년 `해외파생 Open API 사용자 계약서`와 유의사항은 연결 모듈, 해외파생 시세이용료, HTS 팝업을 전제로 하는 별도 상품 문서다. 주문 지연·체결 누락·장애 같은 위험 시나리오는 보수적인 설계 참고자료로 사용하지만, 미국주식 REST API의 계약 근거나 기능 요구로 직접 적용하지 않는다.

## 2. 약관에서 확인한 명시적 의무와 위험

### 자격증명과 데이터

- App Key와 Secret의 유출·도용을 방지하고 제3자에게 대여·위임·양도·누설하지 않아야 한다. (PDF 3쪽)
- 시세정보는 본인의 프로그램 개발과 개인 업무에만 사용하며 제3자 제공·재배포 용도로 사용하지 않는다. (PDF 3쪽)
- 신청, 본인인증, 계좌인증과 회사가 정한 접근·호출 정책을 따라야 한다. (PDF 3~5쪽)

### 호출 제한과 서비스 중단

- 비정상적인 대량 조회로 시스템에 부하를 주면 이용이 중지되거나 반복 시 해지될 수 있다. (PDF 4~5쪽)
- 유지보수, 고장, 통신 두절, 업그레이드, 이용량 폭주, 정전, 불가항력으로 서비스 일부 또는 전부가 제한·중지될 수 있다. (PDF 2~3쪽)
- 점검 중에는 거래내역 반영이 늦어 잔고 등 조회값이 실제와 다를 수 있다. (PDF 5~6쪽)
- 키움은 API 변경을 홈페이지 또는 API 홈페이지에 공지한다. 약관·명세·공지의 현재 상태를 구현 기준으로 삼아야 한다. (PDF 6~7쪽)

### 현재 공식 운영 제약

수치는 구현 시 [REST API 소개](https://openapi.kiwoom.com/intro?dummyVal=0), [이용 안내](https://openapi.kiwoom.com/intro/serviceInfo), [API 가이드](https://openapi.kiwoom.com/guide/apiguide?dummyVal=0), [공지게시판](https://openapi.kiwoom.com/board/Board0101View)에서 다시 확인한다.

- 미국주식 일반시간 계좌·토큰별 초당 주문 10, 조회 5, 환전 1
- KST 09:00~10:00 초당 주문 3, 조회 3, 환전 1
- 미국주식 전체 50 TR/초, 차트 20 TR/초, `usa10099` 5회/분
- 모의투자 동일 TR 1회/초
- 계좌·토큰별 WebSocket 세션 1개, 세션당 실시간 시세 200종목
- 정기 접속 단절 공지가 있으므로 재접속과 전면 대사가 필요하다. [접속 단절시간 공지](https://bbn.kiwoom.com/bbs/VBbsNoticeNOPAZPagingDetailView?seqid=46)

## 3. 구현 통제

| 약관·운영 위험 | 시스템 통제 |
|---|---|
| Key·Secret·계좌번호 유출 | `.env`만 사용하고 Git·로그·원장·예외·테스트 출력에서 차단; 도메인은 내부 계좌 별칭만 사용 |
| 시세 제3자 제공 | 연구·로그·대시보드 경계를 개인 로컬/운영 계정 안으로 제한; 원시 시세 외부 전송 금지 |
| API/TR 변경 | 키움 어댑터에 TR·필드 매핑 집중; 명세 snapshot과 계약 테스트; 배포 전 공지 확인 |
| 호출 제한·차단 | 주문·조회·환전·차트·종목목록별 limiter와 피크타임 정책; 제한 오류 기록 |
| 주문 응답 지연·누락 | 주문 자동 재전송 금지; `SUBMITTED_UNKNOWN` 후 주문·미체결·체결 조회로 대사 |
| WebSocket 단절 | 신규 주문 disarm, 재접속, snapshot 재조회, `RECONCILING -> READY` 재진입 |
| 잔고 시점 불일치 | 구성요소별 관측 시각과 품질을 가진 AccountSnapshot; `CONSISTENT`만 live 사용 |
| 서비스·저장소 장애 | fail-closed; 원장 장애 시 자동 조치를 중지하고 키움 HTS/앱 수동 비상 경로 사용 |
| 실전 오작동 | fake → backtest → 모의 → shadow → 제한 실전의 승격 게이트 |

REST 구현에는 해외파생 문서의 팝업 자동 처리나 별도 해외파생 시세이용료 로직을 넣지 않는다. 영웅문 Global 화면의 주문 유의사항과 키움 REST 공지는 운영 체크리스트로 확인한다.

외부 Codex/OpenAI 모델은 코드 작성·검토 도구로만 사용한다. 키움 App Key·Secret·실계좌번호와 원시 시세·주문·체결·포지션 데이터는 프롬프트, 첨부, 원격 분석 API로 보내지 않는다. 집계·비식별 파생 데이터도 제3자 제공 허용 범위를 확인하기 전에는 로컬 분석으로 제한한다.

## 4. 구현·운영 게이트

### 지금 허용되는 Phase 1A

- 순수 도메인 계약, 위험 규칙, SafetyController
- FakeBroker와 append-only 로컬 원장
- 중복·확정 거절·불확정 주문·재시작 안전 테스트
- `.env`의 Git 차단과 blank example

Phase 1A는 `.env`를 읽지 않으며 네트워크와 실전·모의 주문 엔드포인트를 포함하지 않는다.

### 키움 연동 전 필수 확인

1. 공지게시판과 API 가이드의 변경일·대상 TR을 기록한다.
2. 실전·모의 App Key, 허용 IP, 계좌 allowlist를 분리한다.
3. 응답 스키마와 오류코드를 계약 테스트 fixture로 고정한다.
4. limiter 수치, 재연결, 정기 단절시간을 현재 공지와 대조한다.
5. 주문은 모의 환경에서 timeout, 부분체결, 누락, 재시작 대사를 통과하기 전까지 구현 승격하지 않는다.

## 5. 미확인 사항

- 로그인 후 신청 화면의 추가 안내사항 전문
- 미국주식 모의 환경과 실전의 TR·주문 유형 차이 전체 목록
- 제한 초과 오류별 정확한 코드와 `Retry-After` 보장 여부
- 주문 타임아웃 후 브로커가 보장하는 멱등성 키 또는 고객 주문 식별자 존재 여부

미확인 사항은 허용으로 해석하지 않는다. 확인 전에는 더 보수적인 제한과 수동 대사를 사용한다.
